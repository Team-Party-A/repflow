# RepFlow UI 规范

版本：v0.1 评审稿；日期：2026-10-19；负责人：whj（@whj-thu）。关联任务：[#11](https://github.com/Team-Party-A/repflow/issues/11)。配套文档：[术语表](术语表.md)。

## 1. 范围与设计方向

本稿为 iPhone 与 Apple Watch 原型提供颜色、字号、图标、组件和文案的最小约定。已有需求决定功能边界；本稿新增的视觉取值与交互细节均为评审提案，不表示已获得团队批准或完成真机验证。

建议采用简洁的原生风格：中性背景、蓝色主操作、大号次数、清楚的状态文字。iPhone 侧重编辑与回顾，Watch 侧重抬腕查看和少量点按。两端保持同一语义，布局按屏幕和操作场景分别设计。

- Must 流程：选择动作 → 开始本组 → 自动计次 → 结束本组 → 核对／修正 → 确认并本地保存 → 后续同步。
- 组间休息自动识别、训练模板为 Should；自动识别动作为 Could。UI 不能暗示这些能力已完成，也不增加心率、热量、恢复评分等当前未承诺的展示。
- 系统兼容基线沿用 REQ-NFR-001：部署目标不高于 iOS 17.2.1、watchOS 9.6.3。设计参考当前 Apple 指南，但不依赖仅新系统支持的控件、图标或视觉效果。
- 以下 `pt` 是界面逻辑点；原型中的静态数值用于统一初稿，实施时结合系统语义样式、文字缩放和真机检查调整。

## 2. 颜色

### 2.1 建议色板

iOS 支持浅色／深色随系统；Watch 先以黑色背景设计。下表是本项目原型色板，不是 Apple 系统颜色的精确数值。颜色名称表示用途，不是已经冻结的代码接口。

| 用途 | 浅色 | 深色／Watch | 使用约定 |
| --- | --- | --- | --- |
| 页面背景 | `#F2F2F7` | `#000000` | 大面积背景；Watch 避免大块浅色铺底。 |
| 卡片／输入区背景 | `#FFFFFF` | `#1C1C1E` | 用于记录、表单及次要操作容器。 |
| 主要文字 | `#1C1C1E` | `#F5F5F7` | 动作、次数、正文、关键状态。 |
| 次要文字 | `#56565E` | `#B8B8C0` | 日期、单位及辅助说明；不用于弱化重要错误。 |
| 主操作／选中 | `#005FCC` | `#8CC7FF` | 开始、保存、选中项；不用作所有数字的装饰色。 |
| 成功 | `#176B3A` | `#75D99A` | 配勾选图标及明确文案，区分本地保存与后端同步成功。 |
| 提醒 | `#825000` | `#FFD166` | 待核对、待同步或计次不确定；无需把正常排队画成错误。 |
| 错误／破坏性操作 | `#B42318` | `#FF9B91` | 同步失败、非法输入、删除；正常「结束本组」不使用红色。 |

主按钮：浅色使用蓝底白字，深色／Watch 使用浅蓝底 `#081A2B` 深色文字。次按钮使用卡片背景和主要文字。状态色默认用于背景上的文字与图标，不直接反转为白字彩底，也不降低透明度后假定仍可读。

### 2.2 可读性与状态表达

- 正文、辅助文字和按钮文字以对比度至少 4.5:1 为本稿目标；重要非文字图形／控件边界以 3:1 为目标。实现时检查实际背景、禁用态及增加对比度设置。
- 任何状态同时用文字与图标表达：例如「时钟 + 待同步」「警告 + 同步失败」，不能只用红点／绿点。
- 选中动作同时显示勾选与名称；错误在对应输入项附近说明原因；禁用按钮同时说明尚缺什么条件。
- 原生控件优先沿用系统的外观与无障碍适配；自定义色使用浅／深及高对比度变体，不把整页颜色写死。原型色板需在两端实际组件上复核。

## 3. 字体、数字与布局

### 3.1 字号层级

采用系统字体及系统中文回退，不引入第三方字体。下表为默认文字大小下的原型基准；使用系统语义字体表达层级，字号随用户设置缩放。

| 用途 | iPhone 原型 | Watch 原型 | 字重与说明 |
| --- | --- | --- | --- |
| 页面标题 | 28 pt | 20 pt | Semibold；Watch 长标题允许换行，尽量使用短名称。 |
| 分区／当前动作 | 20 pt | 17 pt | Semibold；必须让用户知道正在计哪个动作。 |
| 正文／按钮 | 17 pt | 16 pt | Regular／Semibold；按钮文字不能为挤入一行而持续缩小。 |
| 辅助文字 | 13 pt | 12 pt | Regular；重要失败说明使用正文层级。 |
| 核心次数 | 48 pt | 40 pt | Semibold，等宽数字；旁边显示「次」，并标明「估计次数」或「最终次数」。 |

- 大号字场景优先换行、纵向排列或滚动，不截断动作名称、状态和主操作。计次数字至少检查 `0`、`10`、`100` 的排版，数值示例不定义产品次数上限。
- iPhone 内容边距建议 16 pt，组件内距 12–16 pt，间距采用 4／8／12／16／24 pt；自定义卡片圆角建议 12 pt。
- Watch 使用原生列表、按钮和安全区，避免复制手机卡片嵌套；计次页按「当前动作 → 次数 → 状态 → 结束本组」纵向排列。所需信息超出屏幕时允许滚动，不用缩字解决。
- 本项目训练场景的主要按钮和加减操作触控区建议至少 44 × 44 pt；这是项目目标，不是对所有系统控件最低值的声明。删除／放弃与保存保持明显间隔，不能靠相邻小图标区分。
- 核心操作有可见入口；滑动、长按或旋转表冠只能作为补充。原型应在小屏 Watch 与大字号下复核。

### 3.2 数值、单位和时间

| 内容 | 显示约定 |
| --- | --- |
| 次数／组数 | `10 次`、`3 组`；使用整数，不能省略语义标签。 |
| 统计 | `训练 2 次 · 3 组 · 动作总次数 30`；手机与 Web 采用同一口径。 |
| 重量 | 始终带已确认的单位，未填写显示「—」；原型可用 `10 kg` 作带注释样例，kg 及记录口径仍待评审。 |
| 日期 | 列表可用「今天 18:30」；详情提供完整日期时间，如 `2026-10-19 18:30`。跨时区显示、周起点需与需求评审对齐。 |
| 休息时长 | 使用 `01:30`，同时写「已休息」或「剩余休息」；不展示含义不明的裸计时器。计时方向、起点及默认值待确认。 |

## 4. 图标

优先用 SF Symbols，采用系统默认风格、单色、与旁边文字一致的字重；同一含义两端使用同一图形。下列是候选符号，开发时在最低系统 SDK 核对可用性；缺失时保留清楚的文字入口，不为图标提高系统版本要求。

| 含义 | 候选符号 | 配套文字／规则 |
| --- | --- | --- |
| 开始本组 | `play.fill` | 开始本组；不能仅显示三角形。 |
| 结束本组 | `stop.fill` | 结束本组；不用删除图标。 |
| 确认／保存成功 | `checkmark` / `checkmark.circle` | 确认并保存／已保存到手表等，文字注明实际结果。 |
| 待传输／待同步 | `clock` | 待传到手机／待同步。 |
| 重试 | `arrow.clockwise` | 重试；不暗示立即成功。 |
| 失败／计次异常 | `exclamationmark.triangle` | 同步失败／计次可能不准，请核对。 |
| 修正／编辑 | `pencil` | 修正次数／编辑记录。 |
| 增减次数 | `plus` / `minus` | 可用图标按钮；辅助功能标签写「增加 1 次」「减少 1 次」。 |
| 删除 | `trash` | 删除训练；需确认。 |
| 历史／设置 | `calendar` / `gearshape` | 历史／设置；不把统计与历史入口混用同一标签。 |

装饰图标不重复朗读；操作图标有语义标签。VoiceOver 需能读出「哑铃弯举，估计次数 10 次」及错误原因；不要因每次数值变化就打断用户当前操作。

## 5. 两端共用组件的最小约定

“共用”指一致的含义和行为，不要求 iOS 与 watchOS 共用同一段控件代码。

| 组件 | 必需内容／行为 | 两端适配 |
| --- | --- | --- |
| 主／次按钮 | 每个步骤突出一个主操作；提交处理中给出反馈并防止重复提交，失败后可恢复操作。 | iPhone 按页面布局；Watch 优先全宽纵向按钮，不并排塞多个主按钮。 |
| 动作选择项 | 动作名称、选中标记、是否支持自动计次；不支持时明确提示。 | Watch 以简短列表为主；手动记录入口若指向手机，要写明「请在手机手动记录」。 |
| 次数显示 | 当前动作、数值、单位、估计／最终的含义。 | Watch 把数值放在视线中心；手机在记录详情保留动作与组序号。 |
| 次数编辑 | 整数输入及清楚的错误提示；取消不改变原确认值。 | Watch 建议加减为主，表冠为可选辅助；iPhone 可用数字输入；上下限沿用评审规则。 |
| 保存／同步提示 | 明确保存位置和传输目的地；状态文字与图标并列。 | 手表侧确认语义待 #19；手机使用需求既定的三种同步状态。 |
| 训练／组记录项 | 动作、组序号、最终次数、重量（如有）、来源；训练详情含同步状态。 | 手机支持需求中的查看与编辑；不因此新增 Watch 完整历史编辑功能。 |
| 空状态／错误区 | 标题、简短解释、适用的下一步入口；加载中、无记录、失败要能区分。 | Watch 文案更短，完整信息可纵向展开或滚动；不能只显示图标。 |
| 确认弹窗 | 明确对象、影响、取消与具体操作，例如「保留」「放弃本组」。 | 删除已保存训练使用系统破坏性操作样式；普通返回不一律弹窗。 |
| 休息计时（Should） | 时长含义及人工纠正入口；次数确认不能重置已经开始的休息。 | 具体起点和退出交互待 #19／算法评审，Must 原型可先保留人工结束组。 |

## 6. 关键状态与统一文案

### 6.1 Watch：组的完成与交接

| 场景 | 建议文案 | 操作与边界 |
| --- | --- | --- |
| 已选择受支持动作 | `哑铃弯举` · `支持自动计次` | 主操作「开始本组」。 |
| 正在计次 | `估计次数 10 次` | 主操作「结束本组」；后续新增计次限于本组。 |
| 结束组、待核对 | `请核对次数` · `10 次` | 可修正；主操作「确认并保存」，次操作「放弃本组」。 |
| 放弃未确认组 | `放弃本组？本组尚未保存，其他已保存的组不受影响。` | 「继续核对」／「放弃本组」。 |
| 本地保存成功、等待手机 | `已保存到手表` · `待传到手机` | 保留记录；具体补发与接收确认由 #19 定义。 |
| 本地保存失败 | `本组尚未保存，请重试` | 保留当前可恢复输入，不显示成功；恢复行为需 #19 补充验收。 |
| 采样异常 | `计次可能不准，请核对` | 不继续伪装正常计次；用户可核对或结束，已确认组保留。 |
| 回放验证 | `回放验证 · 不计入训练记录` | 在验证界面持续显示，不混入真实历史。 |

不得仅凭 Watch 发出消息就显示「已同步到后端」。手机接收成功的判断依赖后续契约，当前草稿不虚构该确认信号。

### 6.2 iPhone：账号、记录与上传

| 场景 | 建议文案 | 操作与边界 |
| --- | --- | --- |
| 待同步 | `已保存到手机 · 待同步` | 允许查看和编辑；上传期间可补充「正在上传」。 |
| 已同步 | `已同步` | 仅对应当前修改已获后端成功确认；再次修改后回到待同步。 |
| 同步失败 | `同步失败，本地记录已保留` | 提供「重试」；明确认证或输入错误时给出对应操作。 |
| 登录失效 | `登录已失效，请重新登录后继续同步` | 提供「重新登录」；不写成网络错误。 |
| 无记录 | `还没有训练记录` | 提供已有需求中的「手动添加」入口；不显示报错。 |
| 加载失败 | `暂时无法加载，请重试` | 保留的数据若展示，注明其范围与更新时间，避免误认为最新结果。 |
| 次数非法 | `请输入有效的整数次数` | iOS 手动记录按现有需求拒绝 0、负数和非整数；Watch 0 次组另待评审。 |
| 重量非法 | `重量不能小于 0` | 保留输入供修改；空值允许保存。 |
| 删除训练 | `删除这次训练？它将从历史和统计中移除，删除结果会同步到后端。` | 「取消」／「删除训练」；不承诺尚未确定的恢复能力。 |
| 有待上传记录时退出 | `还有 N 条记录未上传，仍要退出登录吗？` | 「取消」／「退出登录」；数据保留或清除的说明待 Q3 确认后补全。 |

不向用户展示 API 路径、异常堆栈、原始 token 或内部状态值。重要失败信息保留到用户处理，不仅靠短暂提示。

后续原型／实现走查（本次未执行，不作为已通过的测试记录）：

- [ ] 默认／大字号、浅／深色、小屏 Watch 下，动作、次数、错误信息和主要按钮均可读、可操作。
- [ ] 状态不只靠颜色；按钮与次数有合适的辅助功能标签；开启减少动态效果时无必要信息丢失。
- [ ] 一组估计 9 次改为 10 次后只保存一份；前一组不变；重复确认不新增记录。
- [ ] 待核对、待传到手机、待同步、同步失败可以区分；断网不显示记录已丢失。
- [ ] 0／1／2 次、采样异常、空重量、非法输入、放弃本组和删除训练的路径可检查。
- [ ] 回放与模板不进入真实训练统计；重试／刷新不重复累加。

## 8. 待决问题与参考
