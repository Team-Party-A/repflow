# 需求规格说明书：iOS App

版本：v1 章节评审稿；日期：2026-10-18；章节作者：Wensharre（@wenshare71）。关联子任务：[#18](https://github.com/Team-Party-A/repflow/issues/18)；父任务：[#7](https://github.com/Team-Party-A/repflow/issues/7)。

本节覆盖 D-02 Must 中的「账号」「训练记录增删改查」「历史与统计」，以及「数据同步到后端」的手机侧。账号与同步按 D-03 取最简方案：用户名 + 密码 + token；手机单向上传，同一条记录以最后一次写入为准。后端规则（接口、去重、删除传播）以 #20 一节为准，本节只写手机上可观察的行为。

## 1. 账号

### REQ-IOS-001：注册与登录

- **用户故事**：作为新用户，我希望用用户名和密码注册并登录，以便训练记录归属到我的账号。
- **MoSCoW**：Must。属于 D-02「账号」。
- **验收标准**：
  1. 给定用户名未被占用，当填写用户名和密码注册，那么注册成功并直接进入已登录状态。
  2. 给定用户名已存在，当注册，那么提示「用户名已被使用」，停留在注册页。
  3. 给定密码错误，当登录，那么提示用户名或密码错误，不进入主界面。
  4. 给定已登录，当杀掉 App 后重新打开，那么无需再次登录。
- **负责模块**：iOS（@wenshare71，主要实现方）、后端（@hulaoyagg）。
- **来源**：D-02、D-03。
- **待决问题**：用户名、密码的长度与字符规则由 #20 一节确定。

### REQ-IOS-002：退出登录与登录失效

- **用户故事**：作为用户，我希望能退出登录，登录失效时能重新登录而不丢本地记录。
- **MoSCoW**：Must。属于 D-02「账号」。
- **验收标准**：
  1. 给定已登录，当在设置页点「退出登录」，那么回到登录页，本机不再保留该账号的 token。
  2. 给定本地有待同步记录，当点「退出登录」，那么先提示还有 N 条未上传，用户确认后才退出。
  3. 给定 token 已过期，当 App 发起上传，那么提示重新登录；重新登录后，过期期间的本地记录照常上传，不丢失。
- **负责模块**：iOS（@wenshare71）、后端（@hulaoyagg）。
- **来源**：D-03。
- **待决问题**：退出登录后是否删除本机上该账号的训练数据（本节默认删除）；token 有效期由 #20 确定。

## 2. 训练记录增删改查

### REQ-IOS-003：接收手表的训练并本地保存

- **用户故事**：作为训练者，我希望手表上确认的组自动出现在手机上，以便不用在手机上重复录入。
- **MoSCoW**：Must。属于 D-02「训练记录增删改查」中的「增」。
- **验收标准**：
  1. 给定手表上确认了一组，当手机收到，那么该组出现在对应训练里，显示动作、最终次数和来源「自动计次」。
  2. 给定同一组被手表重复发送，当手机收到，那么本地只保存一份。
  3. 给定手机断网，当收到手表的组，那么照常保存，同步状态为「待同步」。
- **负责模块**：iOS（@wenshare71，主要实现方）、watchOS（@whj-thu）。
- **来源**：D-02、D-03（手表与手机之间只用一种传输方式）。
- **待决问题**：手表与手机断连时的暂存与补发由 #19 一节确定；消息格式写进接口契约。

### REQ-IOS-004：在手机上手动添加训练和组

- **用户故事**：作为训练者，我希望没戴手表或动作不支持自动计次时，能在手机上手动记一组，以便记录完整。
- **MoSCoW**：Must。属于「增」。手动记录不替代 REQ-ALG-001 自动计次的验收。
- **验收标准**：
  1. 给定已登录，当新建训练、选择动作、输入次数并保存，那么该训练出现在历史中，来源显示「手动」。
  2. 给定次数输入为 0、负数或非整数，当保存，那么提示错误并不保存。
  3. 重量可不填；填写时只接受非负数。
- **负责模块**：iOS（@wenshare71）。
- **来源**：D-02、#5（训记「训练—动作—组」的组织方式）。

### REQ-IOS-005：查看训练详情

- **用户故事**：作为训练者，我希望点开一次训练看到每组的细节，以便回顾这次练了什么。
- **MoSCoW**：Must。属于「查」。
- **验收标准**：
  1. 给定一次训练含 2 个动作、共 5 组，当打开详情，那么按动作分组列出 5 组，每组显示最终次数、重量（如有）和来源。
  2. 详情页显示该训练的开始时间、总组数、总次数和同步状态。
- **负责模块**：iOS（@wenshare71）。
- **来源**：D-02。

### REQ-IOS-006：修改训练记录

- **用户故事**：作为训练者，我希望修改记错的次数、重量或动作，以便历史和统计是准的。
- **MoSCoW**：Must。属于「改」。
- **验收标准**：
  1. 给定一组最终次数为 9，当改为 10 并保存，那么详情、历史和统计都使用 10；同一训练中的其他组不变。
  2. 给定一次训练，当在详情页新增或删除其中一组，那么总组数和总次数随之更新。
  3. 给定已同步的训练，当修改，那么同步状态变回「待同步」；上传成功后后端记录与手机一致。
  4. 无效输入的规则同 REQ-IOS-004.2、004.3。
- **负责模块**：iOS（@wenshare71，主要实现方）、后端（@hulaoyagg）。
- **来源**：D-02、D-03（最后写入为准）、REQ-ALG-002。

### REQ-IOS-007：删除训练记录

- **用户故事**：作为训练者，我希望删除误记的训练，以便它不再出现在历史和统计里。
- **MoSCoW**：Must。属于「删」。
- **验收标准**：
  1. 给定一次训练，当点删除，那么先弹出确认；确认后它从历史中消失，取消则不变。
  2. 给定删除了一次训练，当查看统计，那么统计按剩余记录重算。
  3. 给定删除的训练已同步，当网络可用，那么删除同步到后端，Web 看板不再显示该训练。
  4. 给定断网时删除，当网络恢复，那么删除照常同步，且已删的训练不会被重新拉回手机。
- **负责模块**：iOS（@wenshare71，主要实现方）、后端（@hulaoyagg）。
- **来源**：D-02、D-03。
- **待决问题**：删除在后端是物理删除还是标记删除，由 #20 确定。

## 3. 历史与统计

### REQ-IOS-008：历史列表

- **用户故事**：作为训练者，我希望看到所有训练的列表，以便找回任意一次训练。
- **MoSCoW**：Must。属于 D-02「历史与统计」。
- **验收标准**：
  1. 给定本地有 3 次训练，当打开历史页，那么按开始时间倒序列出 3 条，每条显示日期、动作数和组数。
  2. 给定没有任何训练，当打开历史页，那么显示空状态提示，而不是空白页。
  3. 给定断网，当打开历史页，那么本地已保存的训练照常显示。
- **负责模块**：iOS（@wenshare71）。
- **来源**：D-02。

### REQ-IOS-009：基础统计

- **用户故事**：作为训练者，我希望看到本周、本月练了多少，以便了解自己的训练量。
- **MoSCoW**：Must。属于「历史与统计」。
- **验收标准**：
  1. 给定本周有 2 次训练、3 组，最终次数为 8、10、12，当打开统计页，那么本周显示训练 2 次、3 组、动作总次数 30。
  2. 给定把其中 10 次改为 9 次，当回到统计页，那么动作总次数为 29；删除一组后按剩余记录重算。
  3. 回放数据和未确认的组不计入统计。
  4. 统计只展示实际记录的数值，不展示预测重量、1RM 或恢复评分。
- **负责模块**：iOS（@wenshare71）。
- **来源**：D-02、#5、#6（实际记录与预测值分开）。
- **待决问题**：周的起始日（本节默认周一）与时区口径，与 REQ-WEB-002 统一。

### REQ-IOS-010：按动作查看历史与趋势

- **用户故事**：作为训练者，我希望看某个动作历次的组数、次数和重量变化，以便判断有没有进步。
- **MoSCoW**：Should。Must 稳定后再做。
- **验收标准**：
  1. 给定某动作在 3 次训练中出现，当打开该动作页，那么按时间列出这 3 次训练里该动作的所有组。
  2. 给定该动作有重量记录，当查看趋势图，那么每次训练取最大重量画一个点；没有重量记录时不显示该图。
- **负责模块**：iOS（@wenshare71）。
- **来源**：D-02、#5。

## 4. 同步

### REQ-IOS-011：上传到后端与同步状态

- **用户故事**：作为训练者，我希望记录自动上传到后端，并能看出每次训练有没有传上去，以便确认数据安全。
- **MoSCoW**：Must。属于 D-02「数据同步到后端」的手机侧。
- **验收标准**：
  1. 给定已登录且在线，当保存、修改或删除训练，那么自动上传，无需手动操作。
  2. 每次训练显示三种同步状态之一：待同步、已同步、同步失败。
  3. 给定上传失败，当网络恢复或用户点「重试」，那么重新上传；成功后状态变为已同步，后端只有一份记录。
  4. 给定上传失败，那么本地记录不丢失、不被清除，也不显示为已同步。
- **负责模块**：iOS（@wenshare71，主要实现方）、后端（@hulaoyagg）。
- **来源**：D-02、D-03、REQ-NFR-002、#6（同步状态要对用户可见）。
- **待决问题**：时延门槛见 REQ-NFR-003；去重与重试规则由 #20 确定。

## 5. 其他 Should 与不做项

### REQ-IOS-012：训练模板

- **用户故事**：作为训练者，我希望把常练的动作组合存成模板，以便下次开练时少选几步。
- **MoSCoW**：Should。D-02 Should 项。
- **验收标准**：
  1. 给定一次已完成的训练，当选「存为模板」并命名，那么模板列表中出现该模板，包含其中的动作和顺序。
  2. 给定一个模板，当用它开始新训练，那么动作按模板顺序预填；模板里的计划组数不计入历史和统计。
- **负责模块**：iOS（@wenshare71，主要实现方）、watchOS（@whj-thu）。
- **来源**：D-02、#5。
- **待决问题**：模板是否需要同步到手表、是否上传后端，评审时确定。

以下本节不做：找回密码、邮箱验证、第三方登录（D-03）；后端到手机的下拉同步与多设备冲突合并（D-03）；社交（D-02 Won't）；预测重量、1RM、恢复评分。

## 6. 非功能需求

### REQ-NFR-101：本地数据持久化

- **用户故事**：作为训练者，我希望 App 被杀掉或手机重启后，本地记录都还在。
- **MoSCoW**：Must。
- **验收标准**：
  1. 给定有 1 条待同步训练，当强制退出 App 并重启手机，那么该训练和其「待同步」状态都还在，联网后照常上传。
- **负责模块**：iOS（@wenshare71）。
- **来源**：REQ-NFR-002。

### REQ-NFR-102：凭据安全

- **用户故事**：作为用户，我希望密码和 token 不会被明文泄露。
- **MoSCoW**：Must。
- **验收标准**：
  1. token 存放在 Keychain，不写入 UserDefaults 或普通文件；本机不保存密码。
  2. 日志中不出现密码和 token（检查 Debug 构建一次完整的登录、上传流程的日志）。
  3. 后端地址通过不入库的配置注入，仓库中不出现。
- **负责模块**：iOS（@wenshare71）。
- **来源**：AGENTS.md 第 3.3、6 节。

## 7. 本节术语

术语表 #11 尚未合入，本节沿用 AGENTS.md 和 [04 一节](04-alg-web.md) 的叫法，供 #11 对齐：

| 术语 | 本节含义 |
| --- | --- |
| 训练 / 动作 / 组 / 次 | 同 04 一节 |
| 最终次数 | 用户确认（或修正）后用于保存、历史和统计的次数，同 04 一节 |
| 回放 | 对录制数据运行算法的验证模式，不进历史和统计，同 04 一节 |
| 来源 | 一组是「自动计次」（来自手表）还是「手动」（手机录入） |
| 同步状态 | 一次训练相对后端的状态：待同步、已同步、同步失败 |
| 训练模板 | 预存的动作组合与顺序，本身不是训练记录 |
