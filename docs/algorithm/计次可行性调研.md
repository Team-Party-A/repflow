# 计次算法可行性调研

版本：v1 评审稿；日期：2026-10-15；负责人：Nessa（@shooterli）。关联任务：[#12](https://github.com/Team-Party-A/repflow/issues/12)。

## 1. 结论与边界

建议以**平滑后的单轴信号、峰值候选及完整周期状态校验**作为首选方案；用自相关估计周期，作为离线对照，不直接把“时长 ÷ 周期”作为最终次数。首轮先验证腕部运动明显的少量动作，再决定支持动作清单。以上是基于方法复杂度和可观测性的工程判断，尚无本组录制数据，不能宣称准确率已经达标。

依据 D-02/D-03：开组前由用户选动作，组内自动计次；在线算法用 Swift，Python 只做离线评估；不在本任务实现自动动作分类、不修改手表到手机或录制数据契约。自动计次不可靠时，保留原始估计与人工修正入口；若整个动作无法自动计次，应缩小支持范围并在评审中说明，不能把纯手动计数宣称为完成自动计次 Must。

| 层面 | 判断 | 尚需证据 |
| --- | --- | --- |

## 2. 候选方法

以下共同前提是已知动作、用户明确开组/结束组、输入具有真实时间戳。预处理不能使用完整未来数据后再宣称“实时”：Python 离线比较与 Swift 在线版都使用同样的因果平滑、初始化和组尾处理规则。

| 方法 | 原理 | 优点 | 缺点与失败模式 | Swift 实现难度 | 定位 |
| --- | --- | --- | --- | --- | --- |
| A：单轴峰值检测 | 对已选信号平滑；寻找满足幅度、峰间隔和局部突出的候选峰，再结合回落/回位判断一整次动作。[S1] | 简单、容易解释，单次更新可保持固定长度缓存；可定位每次发生的时刻。 | 握持变化使主轴变化；一次动作有多个加速度峰时会重复计数；缓慢动作峰值弱。参数需从开发集得到。 | 低到中：邻点比较、缓存、计时即可；离线 prominence 定义不直接当作在线实现。 | 首选，以完整周期状态校验补足单纯数峰。 |
| B：滑窗自相关 | 去均值信号与其延迟副本相关，在合理延迟范围选重复性强的非零峰，估计周期。[S2] | 可观察节奏和周期性，较适合规则连续运动。 | 短组不足周期；半周期/倍周期歧义；停顿与变速破坏估计；按窗累计容易重叠计数。 | 中：固定长度窗口、延迟范围和置信检查；朴素计算约 O(NK)，N 为窗口样本数、K 为候选延迟数。 | 离线对照与节奏诊断，暂不作为在线最终计数。 |
| C：双阈值迟滞状态机 | 对角度或选定轴信号定义出发、到达、返回三个阶段，完整完成一圈才加一；阈值间有迟滞区。 | 避免阈值附近抖动反复触发；中途停顿可以保持阶段；可解释半次为何不计。 | 依赖姿态/动作的稳定可观测量；佩戴方向与活动范围不同需适配，通用阈值不可靠。 | 中：阶段状态、两级阈值、超时和复位；角度用相对起始姿态，避免欧拉角跨界直接跳变。 | A 的校验与失败动作的备选。 |

方法 C 是本项目的工程候选，不是对 Motra 专有算法的复现。自相关与峰值工具仅作为方法参考，不代表项目已经新增 SciPy 依赖。

### 自相关为何不能直接给出真值

对一段去均值后的信号 x，计算正延迟 k 的相关量：

$$R(k)=\sum_{i=0}^{N-k-1}x_i x_{i+k}.$$

比较不同延迟时需处理有效重叠长度和能量归一化；零延迟不作为动作周期。若候选延迟为 k、有效采样率为 f，则周期估计为 k/f 秒。该量只说明节奏，不说明组的边界是否包含完整动作，因此最终次数仍需事件/完整周期判定。

## 3. 首选处理流程

1. **输入检查。** 开组后只处理该组样本；检查时间戳单调、有限数值、缺帧和采样间隔。异常片段标记无效，不默默补出次数。
2. **选择信号。** 先比较 userAcceleration 的三轴、rotationRate 的三轴及加速度模长。优先选每个动作在开发集上稳定的一条有符号轴；模长可能把一完整动作变成双峰，不能默认一峰一次。
3. **因果平滑。** 起始试验使用约 0.10 秒的移动平均；在 50 Hz 时约 5 点。窗口按实测采样间隔确定，保留组头/组尾样本的处理说明。
4. **候选与完整周期校验。** 找到候选峰后，还需满足幅度、最小峰间隔及回落/回位；完成一整周期才输出一个事件。暂停、结束、切动作时复位；不把单个阈值穿越视为一次。
5. **质量提示。** 采样中断、振幅不足或状态超时，显示“计次可能不准，请核对”，保留已确认次数；人工改动只修改最终记录，不改标注真值或算法评估输入。
6. **回放复核。** Python 与 Swift 对同一段数据输出事件时间与总数，使用相同参数和因果规则比较；回放应有独立标识，不写入真实训练统计。

上述 0.10 秒及后文采样率均为试验初值，不是冻结的产品指标。峰间隔和阈值只用开发集选择，评估前固定，不针对测试人重新调参。

## 4. 采集信号与采样建议

| 数据 | 建议用途 | 说明 |
| --- | --- | --- |
| 单调时间戳 | 周期、间隔、缺帧和事件对齐 | 保存 Core Motion 真实时间，不用样本序号代替时间。 |
| userAcceleration x/y/z | 主计次候选 | 去重力用户加速度；保留三轴以便离线比较。[A1] |
| rotationRate x/y/z | 姿态变化与备选信号 | 关注腕部旋转明显动作，单位按 Apple API 文档记录。 |
| gravity x/y/z | 佩戴方向检查、相对姿态参考 | 不以磁北或场地磁场为前提。[A1] |
| attitude 四元数（可选） | 对比相对角度法 | 若录制成本高首批可省；如加入，记录参考系，不直接比较跨段绝对欧拉角。 |
| 片段元信息 | 分人验证及复现 | 匿名参与者编号、动作、佩戴腕、表冠方向、设备/实际系统版本、组边界、录制程序版本。 |

**采样初值：请求 50 Hz（0.02 秒），同时准备 25 Hz 对照。** 这是起始工程选择，真实间隔可能与请求不同，必须根据时间戳统计有效采样率和间隔分布；Apple 明确要求对时间敏感的程序核对实际时间戳。[A2] 若要从 50 Hz 离线降采样到 25 Hz，先低通抗混叠再抽样，不能简单隔点取样后忽略混叠。

最低兼容基线遵循 D-16：iOS 17.2.1、watchOS 9.6.3；该基线不代表三台手表都安装同一版本。用户确认 Nessa 的手表为 Series 10，其实际系统版本在采集前记录；兼容性验收需在真实的最低系统设备上执行，不能用新设备验证替代。

持续采样应由 watchOS 负责人验证训练会话和后台能力。Apple 说明活跃 workout session 配合相应后台模式可在落腕后继续运行，但过高 CPU 仍可能被挂起，且需要配置和权限。[A3] 本文不指定新 API、不提高最低版本；不要直接照搬最新版文档中的新 API 调用作为 watchOS 9.6.3 的保证。

本节是**采集建议**，不定义文件序列化、字段名、消息格式或传输方式；这些由 Nessa 与 Iridescent 在第 8 周数据契约评审确定。本 PR 不创建或修改 `docs/data/01-sensor-recording-format.md`。

### 标注口径

- 一段录制对应一个组或一个负样本场景；组前后各留约 3 秒静止，标清“准备/有效组/结束”边界，拿放器械不算训练次数。
- 一次：从约定起始姿态出发、完成动作、返回约定起始姿态；半次标为 incomplete，不纳入完整次数。首批双侧同步动作按完整周期计一次，交替单侧动作暂不作为首批支持承诺。
- 标出每次完成时刻、组的真值总数、暂停段和异常段。观察者口头计数与录制标记共同核对；若使用视频复核，先获参与者同意，只拍必要动作，限定团队内使用并单独保管。
- 标注人不得按算法输出反推真值；另一名成员复核全部有分歧片段，未能确认的保留为 ambiguous 并单独报告。
- 保存单位、佩戴腕和表冠方向；同一段的切窗不得分散到开发集和测试集。
- 原始传感器数据、个人对应表及可识别视频均不入 Git。只在仓库保留汇总指标、匿名案例和授权后的示意图；存储位置及保留周期采集前由团队确认。

## 6. 评估方案与推进条件

使用按人留一的三折评估：每次只用两人的数据选择参数，第三人完全留出测试，循环三次。输出各折、各动作结果，并明确样本量；如最终再用所有数据定发布参数，另做独立确认采集，不能把三折结果说成该最终参数的独立成绩。

| 指标 | 计算/报告方法 |
| --- | --- |
| 每组绝对误差 | `abs(估计完整次数 - 标注完整次数)`；同时报 MAE、误差≤1次组占比及最坏组误差。 |
| 漏计/重复 | 根据事件时间与标注一对一匹配；匹配容差先在开发集选定，报告实际值，不用总数相等掩盖重复加漏计。 |
| 负样本误触发 | 按场景报误计总数及每分钟误计，不混入正样本均值。 |
| 延迟 | 完整动作结束到确认事件的时间差，报分布；组尾等待规则单列。 |
| 运行代价 | 记录设备/系统/采样率、前台与落腕连续运行时长、丢帧、CPU/内存和耗电观察。 |
| 失败案例 | 动作、节奏、参与者匿名号、佩戴信息与波形现象；说明是否需要人工修正。 |

**建议评审目标，尚未通过或实测：**每个拟支持动作标准组 MAE≤1 次，至少 90% 组误差≤1 次；负样本平均误计≤1 次/分钟；确认延迟 P95≤1 秒。门槛需在需求评审确认，不能据此写“达到 90% 准确率”，也不能拿它替代分动作失败分析。

## 7. 降级方案

1. 峰值法在某动作双峰/抖动明显：比较有符号轴、调整平滑和完整周期状态校验，只用开发集调参。
2. 峰值弱但角度周期清楚：对该动作验证相对姿态双阈值方案，比较实际错误，不自动增加复杂模型。
3. 该动作腕部信息不足：明确标为自动计次暂不支持，保留手动记录；由需求评审缩小支持动作清单。
4. 整组采样中断或异常：停止继续自动累加，提示用户核对并手动修正，已有确认记录保留。
5. 若没有任何动作达到团队确认的门槛：报告自动计次 Must 尚未完成，并提交风险与排期调整；回放只作备份演示，不能作为现场实时计次成功的证据。
