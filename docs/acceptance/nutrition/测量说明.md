# 饮食识别联调参考

这份资料包含 20 份公开餐盘的参考值和空白的观测栏。可在同一批照片上复查模型、食物匹配与营养计算的表现。iPhone 真机拍照、相册选择、人工纠正和真实模型用量在联调时另行测量。

## 手动记餐联调

用固定的测试标签录入熟米饭，每 100 g 含碳水 28 g、蛋白质 2 g、脂肪 0 g、能量 120 kcal。通过 App 使用的 Swift 网络客户端保存 200 g 后改为 120 g，隔离 PostgreSQL 返回的单餐和当天合计均为 33.6 g 碳水、2.4 g 蛋白质、0 g 脂肪、144 kcal。删除后当天合计归零。

## 数据来源与选样

来源为 Quin Thames 等人的 Nutrition5k（CVPR 2021），许可为 CC BY 4.0。本资料从原表选取部分行，重新排列营养列、新增分组与本地样本编号。保留原 dish_id 和 ingredient_id 以供追溯。[数据集说明](https://github.com/google-research-datasets/Nutrition5k) · [许可](https://creativecommons.org/licenses/by/4.0/) · [餐盘与逐食材参考数据](https://storage.googleapis.com/nutrition5k_dataset/nutrition5k_dataset/metadata/dish_metadata_cafe1.csv)

选样限定为 RGB 与深度测试集的交集；实际识别只传普通 RGB。6 份为单品，7 份含至少三种食材，另 7 份的元数据记录了至少 1 g 的油或酱料。按公开 ID 的确定性哈希排序选取，各样本的日期和食材组合均不同，避免连续加菜拍摄造成重复。实测前排除了食材名称为 deprecated 或 unknown 的样本，按同一顺序替补一份混合餐。20 张 RGB 原图均已核对。

Codex 在方舟推理前逐张查看了俯拍 RGB，对照参考条目标记可见性。40 项能辨认（visible），29 项仅有可疑线索或不能分辨品种（uncertain），35 项在此角度无法辨认（not_visible），包括多项油、盐和醋。标记写入 observations-items.csv，原始和修正阶段共用同一组参考。

原料克数采用数据集标注，配方拆分值保留原精度；营养参考值来自数据集采用的成分资料。该批样本采自美国食堂，对中国菜和家庭手机拍摄条件的表现需另行观察。

## 使用文件

| 文件 | 内容 |
| --- | --- |
| reference-meals.csv | 20 个餐盘的分组、参考总重、碳水、蛋白质、脂肪、能量和原图链接 |
| reference-items.csv | 对应的 104 条食材参考记录。每餐逐项合计与原始餐盘参考值在 0.1 g 或 0.1 kcal 内一致 |
| observations-meals.csv | 每餐分别记录原始输出和用户确认后的结果。模型调用次数、用量、费用及处理耗时记在发生调用的阶段 |
| observations-items.csv | 匹配到的食材、漏识、误识及用户修正的逐项观测。模型多报的食材也应追加行 |

## 实测口径

1. 先按原图标注主要可见食材。单列看不见的油、酱汁和配方成分。只给模型图片，称重值、参考营养素和文件 ID 留在计分端。
2. 第一次模型结果原样记入 raw。用户仅凭正常确认界面操作，保存后的结果记入 user_confirmed。缺失项或失败值留空并填写原因，真实的零填 0。重试与更换模型另开一次运行记录。
3. 按样本和食材对齐，一对一核对识别结果。报告正确、漏识和误识数量，并列出可见与不可见的分母。匹配成功项的克数 MAE 为克数绝对误差之和除以有克数的匹配项数，同时报覆盖数。
4. 对每餐的四项营养分别报告绝对误差（g 或 kcal）和相对参考值的绝对百分比误差，两阶段分开统计。参考为零时只算绝对误差。报告总样本数、成功数、失败数、缺失数和各分组结果。
5. 处理耗时从任务被接受到客户端首次读到完成状态。库命中率为查到已核实或已缓存 AI 条目的不同食材数除以本轮查找的不同食材数。记录模型标识、输入/输出用量、对应费率来源和币种后计算单餐费用；免调文字模型的餐次仍可能发生视觉调用费用。

真实模型输出、用户修正、时延和费用栏目前都待实测。已受理但失败的任务也保留任务 ID，计入有观测的耗时和费用。营养误差按成功且有对应数值的样本计算。参考图片通过原始链接访问。

## 复跑

在 Mac 上对独立测试环境运行 `python3 scripts/nutrition_benchmark.py capture --api <测试服务> --output <新运行目录>`。脚本使用本机 sips 转码，创建一次性测试账号，按顺序只向模型提交 RGB，保留每餐返回的任务 ID、食材草稿和端到端耗时。若需从 iPhone 修正并保存，先建共用的隔离测试账号，用 `--username` 登录，密码通过交互输入。补录时运行 `python3 scripts/nutrition_benchmark.py confirm --api <测试服务> --username <账号> --confirmed <餐盘到餐次UUID的JSON> --output <原运行目录>`，该命令只读取已保存餐次。费用及查库统计使用服务端 `nutrition_admin metrics` 的任务级输出，在原始采样后运行 `python3 scripts/nutrition_benchmark.py metrics <运行目录> <指标目录>` 回填即可。

逐项对齐使用 matched、missed、extra。模型报出的食材若在图上清楚可见、但称重表未单列，另起一行标 visible_unlabelled，参考 ID 留空。例如 N11 的沙拉里可见胡萝卜丝，成分表只列了综合莓果、菠菜和橙子。此类单列，不计作误识。确认阶段取 App 保存后的实际数据；可见性沿用采样前的标注。运行 `python3 scripts/nutrition_benchmark.py score <运行目录>`，结果按阶段和分组给出有效样本数、误差和成本。空白模板只报告未测。
