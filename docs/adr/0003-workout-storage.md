# ADR 0003：训练数据、删除标记与事务边界

状态：共同评审稿，后端负责人已 review，待 iOS 核对映射及 IOS-02 后定稿；2026-11-01；关联 [#57](https://github.com/Team-Party-A/repflow/issues/57)。

## 背景

[OpenAPI 1.0.0](../api/openapi.yaml) 已要求完整训练原子覆盖、同版本同内容幂等、固定账号／组 ID 归属，以及未知 ID 删除也留标记。[iOS 已确认](../design/概要设计-iOS.md) 用 SwiftData 保存内容与上传快照，删除及组 ID 标记不过期；服务端无需与手机逐表对应。账号两表已由 #76 实现。

本 ADR 只决定建议的存储和事务方式，不重新讨论技术栈或修改接口。字段、ER 图与客户端待确认项见[数据库设计](../design/数据库设计.md)。

## 可选方案与建议

| 决策 | 其他方案 | 建议与代价 |
| --- | --- | --- |
| 内容和 ID 归属 | 整条 JSONB；关系表另加删除／ID 登记表 | `workouts`＋`workout_sets` 两表，ID／归属永久保留，删除后清空内容列。字段约束与查询直接；代价是需要明确有效／删除两种空值形态，所有正常读取都要过滤标记 |
| 同版本内容判断 | 另存规范化 JSON 快照或哈希 | 从当前关系字段还原完整输入后逐字段比较。避免重复存储和只凭哈希判断相等；代价是比较时需要读取至多 1000 组 |
| 并发写入 | 单靠事前查询；仅对已存在行加锁 | 主键冲突协调首次创建，再锁训练行并在同一事务中核验版本、登记组和替换内容。无需额外锁服务；代价是同一训练写入串行、必须处理冲突与回滚 |
| 一次查询内的一致性 | READ COMMITTED 下分两次独立查询父、子记录 | 短暂的只读 REPEATABLE READ 事务中分页训练、加载组。防止单次响应混合两个版本；代价是读取期间保留快照，事务须及时结束，不扩展为跨页快照 |

## 决策边界

- 关系表保留未知 ID 删除所需的最小身份信息；不通过虚构开始时间满足非空列，也不物理删除组 ID 后允许其转移。
- ID、唯一位置、同一行的范围／空值关系交给数据库约束；组数、IANA 名称和共享动作名单由应用校验。重排先将旧组置为完整移除形态，再在同一事务内恢复新数组，保证每条 SQL 都符合 CHECK／唯一约束。CHECK 不负责跨行计数，nullable 范围检查不能代替必填。[PostgreSQL 约束](https://www.postgresql.org/docs/18/ddl-constraints.html)
- `INSERT … ON CONFLICT` 与随后行锁共同处理“不存在”的竞争；失败回滚包括本事务新建的 ID。多组登记采用固定顺序，缩小死锁风险；锁超时或数据库故障仍须按契约失败，不返回假成功。[行锁](https://www.postgresql.org/docs/18/explicit-locking.html)、[隔离级别](https://www.postgresql.org/docs/18/transaction-iso.html)
- 正常查询只读当前账号；游标不是凭据。单次读取的一致性不改变契约“不保证跨页快照”的约定。
- 不增加数据库枚举类型、动作表、消息中间件或新依赖。规模增长时先测量，再决定是否增加索引、归档或存储副本；删除／去重保留策略如要改变，须重新评审。

## 验证与后果

删除后的本地永久保留已在 #77 明确；字段映射及结束交接等元数据落点仍需 iOS 共同审查，不能代填批准。#62 用真实 PostgreSQL 验证首次写入竞争、版本幂等、组归属冲突、整体回滚、删除重放和一致读取；#65 验证账号隔离、事务持久化及晚到回执。迁移及性能结果不由本 ADR 代替。
