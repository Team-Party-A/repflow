# 后端压测操作（#130）

负责人选择没有发布或联调的时段，在具备 `swe` SSH 访问权的 Mac 上从仓库根目录运行。使用后端锁定的 uv 0.13.5 和 HTTPX。入口从公开证书取得 HTTPS 目标，服务密码和 token 均留在各自进程中。

```sh
uv --directory backend run --locked python -m scripts.benchmark_online --start
```

终端显示当前提交和服务检查结果。输入 `START 130` 发起一轮新测试，直接回车退出。运行同一命令时省略 `--start` 可只读检查发布和服务健康。每轮生成独立的私有目录、专用随机账号和清理清单。启动前核对 API 容器与登记镜像，测试期间监控发布状态。

- 按并发 1、2、4 分别测登录、上传和分页。每个阶段先按该档并发预热，再取 50 个样本。分页使用同一账号的 21 条固定记录、每页 10 条、真实游标，校验两页记录互不重复。每次上传生成独立的训练和组 ID。
- 每阶段前后检查健康。连续三次失败、监控中断、发布变化、600 秒压测时限或负责人按 Ctrl-C 时结束测量。资源采样有独立的 690 秒时限。HTTP 清理另限 45 秒。
- 脚本先清理 API 训练与会话，再用本轮专用用户 UUID、随机用户名、创建时间和行数上限核对归属，执行事务清理并在提交后复核。注册归属不明时保留清单，由负责人复核。SQL 的默认模式只预览，指定应用模式才会删除已匹配的本轮数据。
- 终端显示该轮的私有目录。请向跟进人提供目录名，以便核对 `report.json`、`resources.jsonl`、`cleanup.json` 及两次发布记录。`identity.json` 只供定向清理。公开报告保留版本、数量与聚合指标。资源按首末计时阶段的时间戳筛选，报告 CPU 和内存的实际采样峰值。
