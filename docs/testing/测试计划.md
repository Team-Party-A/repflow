# RepFlow 测试计划

版本：v0.1；日期：2026-10-31。关联 [#71](https://github.com/Team-Party-A/repflow/issues/71)。

本计划说明各模块的测试范围、方法、用例记录及阶段交付。核心验证链路为手机手动记录上传，以及手表自动计次、用户核对后经手机上传。执行结果随实现进度记录，不将计划中的用例写成已通过。

## 1. 测试依据与范围

测试用例引用[需求规格说明书](../requirements/需求规格说明书.md)中的 REQ 编号，字段和交接规则分别以 [OpenAPI](../api/openapi.yaml)、[手表与手机消息契约](../data/02-watch-phone-messages.md)及[录制数据格式](../data/01-sensor-recording-format.md)为准。

| 范围 | 重点 | 需求依据 |
| --- | --- | --- |
| 账号 | 注册、登录、退出、登录失效及账号间记录隔离 | REQ-IOS-001–003、REQ-BE-001–003、REQ-NFR-102/301 |
| 手机训练记录 | 新建、查看、编辑、删除、历史和基础统计 | REQ-IOS-004–009、REQ-NFR-101 |
| 同步 | 本地保存、重复交接、断连补发、版本更新与删除传播 | REQ-IOS-003/011、REQ-WATCH-004–006、REQ-BE-004–007 |
| 手表计次 | 选择动作、开组、显示估计、结束核对、确认保存 | REQ-WATCH-001–005、REQ-ALG-001–003 |

Must 核心流程优先。自动休息、训练模板、动作趋势和 Web 看板等 Should 功能在相应实现阶段补用例；本次不扩展功能范围。

## 2. 测试层次、工具与覆盖率

| 模块 | 现有工具与执行方式 | 主要测试对象 | 覆盖率安排 |
| --- | --- | --- | --- |
| iOS | XCTest，`RepFlow` scheme | 本地记录、账号归属、接收及上传状态处理 | 统计业务逻辑的代码覆盖率；采集方式与数值目标待 iOS 模块确认 |
| watchOS | XCTest，`RepFlowWatch` scheme | 组状态、录制数据、计次和待传记录 | 统计录制、计次及交接逻辑；采集方式与数值目标待 watchOS 模块确认 |
| 后端 | pytest、HTTPX、测试 PostgreSQL、pytest-cov | 参数与鉴权、接口、持久化及事务结果 | 现有配置统计 `app` 并启用分支覆盖；数值目标待后端模块确认 |
| 算法 | pytest、现有 Python 格式检查器 | 信号处理、完整周期、事件及指标计算 | 统计计次与评估代码；覆盖率工具和数值目标待算法模块确认 |
| 原型与部署 | Node 原型回归、现有 Compose 检查脚本 | 原型状态流、数据库故障恢复与服务入口 | 保留用例及执行记录，不与业务代码覆盖率混算 |

各模块确认时记录工具、统计目录、行/分支口径、目标值及依据。覆盖率数字不填入未确认的门槛，界面走查、真机测试和算法准确率分别保留证据。

命令沿用[工程规范](../../AGENTS.md)和[Apple 工程说明](../../apps/apple/README.md)：

- iOS/watchOS：Swift 格式检查、双端构建及两套 XCTest；结果保留 `.xcresult` 或对应 CI 链接。
- 后端：`uv run --locked pytest --cov=app --cov-report=term-missing`，配合 Ruff；完整测试环境及 Compose 命令见[部署说明](../deployment.md)。
- 算法：`pytest ml` 与 Ruff；格式互通使用 `apps/apple/check-recording-format.sh`。
- 原型：`node --test docs/prototype/watch.test.cjs`。原型回归结果与真机交接结果分开记录。

## 3. 接口与集成测试

后端接口在独立测试库中执行，使用 HTTPX 调用应用，按 OpenAPI 检查状态码、响应字段和数据库中的最终记录。重点包括账号生命周期、账号隔离、训练完整写入、相同版本重复提交、旧版本冲突、删除后的重放及查询结果。

跨端集成以已配对的 iPhone 与 Apple Watch 执行：手表确认一组并保存，手机持久化后回业务确认，再上传后端。分别核对手表保存状态、手机接收状态和后端同步状态；同一条记录在各处只出现一次，原始估计与用户最终次数分别保留。

恢复场景聚焦两条：手机无外网时保存后补传；手表与手机断连时暂存、恢复后补发。再验证手机编辑后的版本不会被旧回执或重复手表消息覆盖。测试账号和数据与真实使用记录分开，测试日志不包含密码和 token。

用例采用以下字段。本版按作者确认的字段起草，课程指定模板如有差异，再核对调整。

| 字段 | 填写内容 |
| --- | --- |
| 用例编号 | 稳定编号，如 `TC-IOS-001` |
| 关联 REQ | 需求及具体条目，如 `REQ-IOS-004.1` |
| 测试目的 | 本例验证的用户可观察结果 |
| 前置条件 | 登录、已有记录、连接及权限等必要状态 |
| 环境 | 提交版本、App 版本、设备、系统与网络条件 |

| 预期结果 | 界面、记录及同步状态应如何变化 |
| 实际结果 | 本次实际观察到的结果 |
| 执行状态 | 通过、失败、阻塞或未执行 |
| 证据 | CI、截图、录屏、统计输出或关联缺陷链接 |

核心用例索引如下，实施时按模板展开。索引用于安排测试，执行记录单独填写。

| 编号 | 场景与预期结果 | 关联需求 |
| --- | --- | --- |
| TC-ACC-001 | 注册、登录后记录一组；退出再登录同账号仍可见，换账号不可见 | REQ-IOS-001/002、REQ-BE-003 |
| TC-IOS-001 | 手机录入 8 次并保存，详情与历史一致；改为 10 次后统计采用 10；删除后不再显示 | REQ-IOS-004–009 |
| TC-SYNC-001 | 手机断网保存，恢复后上传成功；重复发送不增加训练或组 | REQ-IOS-011、REQ-BE-004/005/007 |
| TC-SYNC-002 | 手机编辑后收到旧回执或重复手表消息，保留编辑结果；已删除训练不被补发恢复 | REQ-IOS-003/006/007、REQ-BE-005/006 |
| TC-WATCH-001 | 弯举开组从 0 计次；估计 9 次，核对改为 10 次后保存，估计与最终次数分别保留 | REQ-WATCH-001–004、REQ-ALG-001/002 |
| TC-WATCH-002 | 手表断连保存两组，重启后仍可找到；恢复连接后手机各接收一次 | REQ-WATCH-004–006、REQ-NFR-201 |

## 5. 真机与性能测试

最低系统基线按工程规范采用 iOS 17.2.1、watchOS 10.0 真机。模拟器和 CI 验证构建及逻辑；最低版本安装、现场计次、落腕运行和无线交接由对应真机记录验证。记录实际型号与系统，不用目标版本代替设备版本。

| 项目 | 测量方法 | 输出 |
| --- | --- | --- |
| 采样连续性 | 脱离 Xcode 调试器，包含抬腕及落腕录制；按真实时间戳统计 | 时长、请求/有效频率、间隔分布、最大缺口及尾部间隔 |
| 计次延迟 | 对齐人工动作完成时刻与算法结果确认时刻 | 延迟分布、P95、动作及采样配置 |
| 同步时延 | 分别测手表确认至手机可见、手机保存至后端可查、网络恢复至积压上传完成 | 测量次数、记录数量、设备网络条件及耗时分布 |
| 后端性能 | 在测试环境对实际账号、训练写入及查询接口施加可复现负载 | 请求量、并发条件、响应时间、错误率及服务器配置 |
| 手表运行代价 | 固定动作与时长，记录采样和计次期间资源及电量变化 | 设备、时长、CPU/内存与耗电观察、异常情况 |

同步时延 X/Y/Z、误差和采样中断等待评审指标，沿用统一需求第 3 节的实测定稿流程；不在本计划新增数值。后端负载规模由后端模块结合测试环境确认。性能报告注明测量方法与重复次数，使后续版本能够复测比较。

## 6. 算法准确率评估

方法沿用[计次可行性调研](../algorithm/计次可行性调研.md)及[算法概要设计](../design/概要设计-算法.md)。使用经独立标注复核的数据，按人留一：两人用于选信号与参数，另一人留出测试，轮换三次。同一片段及其切窗不跨开发与测试两侧，事件匹配容差在测试前固定。

报告按动作、参与者和组长列出实际样本量、每组误差、MAE、误差不超过 1 次的组占比及最坏组；事件一对一匹配后计算 precision/recall。负样本按场景报告误计及每分钟误计；短组、暂停、半次和不确定片段另列。组内真值不确定时，不计算该组总数误差；事件评估只使用真值可判定的区间，分母为零记 N/A。

首批动作及自动计次范围取[共享清单](../../apps/apple/Shared/Exercise.swift)：弯举、肩推进入首批自动计次评估，持哑铃深蹲先验证信号。Python 与 Swift 使用相同参数和因果规则回放，比对总数、事件及组尾处理。合成数据用于测试计算流程，正式误差结论来自真实留出数据；用户组后修正值不替代算法原始估计。

## 8. 结果维护与待确认项

失败用例记录实际结果、复现步骤与关联 Issue；修复后在对应版本复测，保留原失败记录。功能尚未实现记为未执行，环境或依赖不可用记为阻塞。每次检查汇总仍影响核心流程的问题，不以覆盖率代替功能验收。

本计划定稿前需要对应模块确认第 2 节的工具、覆盖率统计范围和数值目标。后端负载规模在性能测试准备时确认；用例字段由作者按课程要求核对。本版未新增依赖或修改 CI，既有检查继续运行。
