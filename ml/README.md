## 计次基线与样例运行（#73）

~~~sh
python3 ml/evaluate_recordings.py docs/data/samples/synthetic-v1.json
~~~

脚本先用现有检查器校验输入，再按 `set` 边界运行有符号轴、因果时间窗均值及峰值/回位基线：先观察到低位，达到 `peak` 后回落到 `release` 才计一次。开始时处于高位、半次后结束或只在高位停顿，不补计完整周期。每段独立初始化；超过配置缺口时清空平滑与周期状态，保留此前已确认事件。

这是一条可解释的初始基线，具体动作的轴和参数尚待开发数据选择。所有默认数值是让样例跑通的**试验参数**，不是准确率承诺或已评审的采样门槛：

| 参数 | 初值 | 含义 |
| --- | --- | --- |
| `--field`、`--axis`、`--sign` | `user_acceleration_g`、`x`、`1` | 加速度或角速度的有符号轴，不改变原始文件 |
| `--window-s` | 0.1 秒 | 仅用当前及过去样本做窗口均值 |
| `--peak`、`--release` | 0.15、0.05 | 达峰与回位阈值；单位随所选字段为 g 或 rad/s |
| `--min-interval-s` | 0.4 秒 | 两次确认间的最小间隔 |
| `--max-gap-s` | 0.2 秒 | 重置周期状态的采样缺口阈值 |
| `--event-tolerance-s` | 0.2 秒 | 预测完成事件与人工真值的一对一匹配容差 |

输出记录 `baseline_version`、全部参数、每段预测事件/总数、采样缺口数及实际处理样本数。`t_s` 是算法判断已回位的事件时间，`confirmed_at_s` 是输出该结果的时间；本基线二者相同，不回填为峰顶时间。与人工完成时刻的偏差需要真实标注数据测量。组尾不使用后续样本，也不补未完成事件。

现有合成样例的 `ground_truth_count=null`，因此只得到预测及采样统计，MAE 等整组指标为 `null`。样例只演示格式和执行流程，不能据此声称算法达到准确率要求。

## 使用标注数据评估

在自己的电脑本地运行，输入和输出都放仓库外：

~~~sh
python3 ml/evaluate_recordings.py "/私有目录/annotated/片段一.json" "/私有目录/annotated/片段二.json" \
  --field user_acceleration_g --axis x --sign 1 \
  --peak 0.15 --release 0.05 > "/私有目录/评估结果.json"
~~~

- 只对已确认总数的动作组计算绝对误差、MAE、误差不超过 1 次的占比与最坏组；总数未知时不把已知事件数量当作整组真值，事件指标也暂不计入。
- 预测与真值事件按时间有序、一对一匹配，重复预测进入 FP，未匹配真值进入 FN。precision/recall 分母为零时输出 `null`。
- 负样本单列误计总数及每分钟误计，分母采用完整录制时长；含不确定区间的负样本不纳入误计汇总。
- 汇总按 `data_kind` 隔离，合成与真实数据不会混算，并按动作、参与者和真值次数分层。每段结果保留在 `recordings` 中，便于查最坏组与失败案例。
- 标准组与短组、半次、暂停等特殊实验由采集清单区分，分次运行和保存结果，不将所有场景混成一个“准确率”。有缺口的片段需结合采样记录先质检，脚本不会替观察者认定其可用。

脚本执行给定参数，不自动训练、选轴或分配开发/测试集合。按人留一时，先用两人的开发数据选参数与匹配容差，再固定参数评估另一人，轮换三次。重复使用同一录制编号会报错，避免原始与标注副本重复入评估。

正式结论等待 #74 数据及人工标注复核后给出。原始文件不改写，不提交仓库，也不上传 AI 对话；可交付匿名汇总、方法与失败分析。格式、参数或文件错误退出码为 2，成功输出 JSON、退出码为 0。
